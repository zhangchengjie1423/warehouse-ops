# 仓衡 · 仓储运营分析与人效管理

第二个个人实践项目：围绕订单履约、拣货效率、异常跟进和排班测算，形成从原始数据到运营行动的完整流程。Python 标准库 + SQLite + 原生 JavaScript，无第三方依赖。

## 启动

Python 3.10+，Windows 双击 `start.bat`，或执行 `python app.py --demo --open`。默认地址 `http://127.0.0.1:8767`。演示数据为程序生成，不代表企业经营记录。

## 统计口径

- 时间统一为北京时间。筛选日期按自然日包含首尾，最长 366 天。
- 履约统计按订单创建日归属；取消单从履约分母中排除。准时率 = 准时送达单 / 已送达单；履约完成率 = 已送达单 / 非取消单。待履约超时依据当前时间与承诺送达时间比较。
- 拣货效率按拣货完成日归属。按日期、站点、拣货员匹配拣货工时；缺失工时的数据单独提示，不将缺失视作 0，不纳入团队效率分子。
- 件/人时 = 匹配到工时的拣货完成件数 / 拣货工时。该指标不等同于个人绩效评级。
- 阶段用时：接单至开拣、拣货、复核等待及包装、出仓至送达。只对已记录对应时间的订单计算，不填补缺失时间。P90 使用最近秩法。
- 排班为参数情景测算：每小时预测件数 /（件/人时 × 有效作业比例），向上取整。未考虑轮班、技能、休息时段和跨时段积压，结果为需求人数，不是实际员工排班表。

## 本地数据

SQLite 保存订单、工时、导入批次和异常处理记录。CSV 导入先预检再整批提交；任一错误阻止整批写入；重复且相同的业务记录自动跳过，同键不同内容报错。已有订单更正需使用独立新数据库，当前不提供覆盖历史记录功能。

## 功能

| 模块 | 已实现 |
| --- | --- |
| 运营概览 | 日期/站点筛选，准时率、履约完成率、有效订单、人效、待跟进异常，日趋势与小时分布 |
| 过程诊断 | 等待开拣、拣货、包装出仓、配送阶段平均耗时与 P90；订单时间线与分页查询 |
| 拣货人效 | 员工工时与产出关联，团队加权人效，漏报工时提示，人员明细导出 |
| 异常跟进 | 超时/缺货/差错/货损识别；待处理、处理中、已解决；负责人、处理说明与历史记录 |
| 排班测算 | 历史小时件量，增长率、标准效率、有效作业比例与可用人数情景测算，缺口计算与导出 |
| 数据中心 | CSV 模板、示例下载，预检与整批导入，重复跳过、冲突拒绝，导入日志与数据库备份 |

## 10 分钟演示

1. 启动演示工作区，默认展示最近 7 个有数据的自然日范围；模拟源含 28 天、2 个站点、12 名拣货员。
2. 筛选东湖站，观察准时率及四段耗时；打开订单明细查看时间线。
3. 在“异常跟进”打开一笔超时订单，填写跟进人，切换“已解决”并填写处理说明；保存后查看历史记录。
4. 在“数据中心”下载订单与工时示例，分别预检、导入；重复导入时应提示跳过。
5. 切到“拣货人效”，筛选“样例站”：12 件 / 7.5 人时 = 1.6 件/人时。
6. 在“排班测算”使用今天日期，设置增长率 10%、效率 60 件/人时、有效作业 85%、可用 3 人，查看峰值与缺口；修改参数重新计算。
7. 导出订单、人效、异常台账和测算结果；下载数据库备份，重启后确认记录保留。

附带 samples/ 中的 CSV 为生成当日的固定样例；网页下载的示例时间会跟随当天更新。

## 空白工作区和备份恢复

开始自己的数据集：

    python app.py --db data/my-operations.db --port 8768 --open

恢复：停止目标服务，将下载的数据库放到 data/ 下，以新文件名启动：

    python app.py --db data/restored.db --port 8768 --open

不带 --demo 时不会注入演示数据。--demo 只在订单和工时均为空时生成数据，不覆盖已有记录。

## API

GET /api/meta 返回工作区信息与会话 token；POST 请求使用 JSON，并将 token 放入 X-App-Token 请求头。

| 接口 | 参数 / 功能 |
| --- | --- |
| GET /api/report | start、end、station；汇总及明细 |
| POST /api/import/preview | kind（orders/shifts）、filename、content |
| POST /api/import/commit | 同预检；事务中再次校验 |
| POST /api/followup | order_id、state、owner、note、version |
| GET /api/history | order_id；异常跟进历史 |
| POST /api/staffing | date、station、growth、productivity、utilization、available |
| GET /api/export | kind（orders/workers/exceptions/trend）、start、end、station |
| GET /api/template 或 /api/sample | kind（orders/shifts） |
| GET /api/backup | 下载一致性 SQLite 快照 |

## 使用边界

这是本地个人实践应用，绑定 127.0.0.1，不含账号权限、实际员工排班、AI 模型调用或企业系统对接。跟进人是手工记录字段。当前统计读取筛选内明细，适合学习与小规模展示；未验证大型仓库数据量性能。取消单不进入异常台账；同日工时关联不验证每张订单是否位于具体班次内。异常“已解决”只改变处理台账，不改原始订单事实。

简历可写“个人实践项目：实现订单与工时数据清洗、履约与人效分析、异常跟进及排班需求测算”，使用真实实现与测试结果，不填写企业落地或业务提效百分比。
